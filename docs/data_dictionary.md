# Data Dictionary – `retail` schema (PostgreSQL)

All data is synthetic, generated by `sql/02_seed_data.sql` (seeded, so every build is identical).
Period covered: **1 Jul 2024 – 30 Jun 2026** (fiscal years FY2025 and FY2026; the fiscal year starts 1 July).

## Tables

### `regions` (5 rows)
| Column | Type | Description |
|---|---|---|
| `region_id` | smallint, PK | Region identifier |
| `region_name` | text, unique | Northeast, Southeast, Midwest, Southwest, West |

### `stores` (12 rows)
| Column | Type | Description |
|---|---|---|
| `store_id` | smallint, PK | Store identifier |
| `store_name` | text | Store name |
| `region_id` | smallint, FK → regions | Region the store is located in |
| `channel` | text | `Store` or `Online` (CHECK constraint) |
| `opened_on` | date | Opening date |

### `categories` (8 rows) and `products` (64 rows)
| Column | Type | Description |
|---|---|---|
| `category_id` | smallint, PK | Laptops, Monitors, Accessories, Audio, Networking, Storage, Office Furniture, Software |
| `product_id` | integer, PK | Product identifier |
| `product_name` | text | Product name |
| `unit_price` | numeric(10,2) | List price, must be > 0 |
| `unit_cost` | numeric(10,2) | Cost to the business, must be > 0 |

### `customers` (4,000 rows)
| Column | Type | Description |
|---|---|---|
| `customer_id` | integer, PK | Assigned in signup order |
| `first_name`, `last_name` | text | Fictional names |
| `email` | text, unique | `customerN@example.com` |
| `region_id` | smallint, FK → regions | Customer's home region |
| `signup_date` | date | Account creation date |
| `segment` | text | Consumer, Small Business or Corporate (CHECK constraint) |

### `orders` (~44k rows)
| Column | Type | Description |
|---|---|---|
| `order_id` | integer, PK | Order identifier |
| `customer_id` | integer, FK → customers | Buyer; never dated before the customer's signup |
| `store_id` | smallint, FK → stores | Where the order was placed |
| `order_date` | date | Order date |
| `status` | text | Completed, Cancelled or Returned (CHECK constraint) |

### `order_items` (~92k rows)
| Column | Type | Description |
|---|---|---|
| `order_id`, `line_no` | composite PK | One row per order line; deleting an order cascades to its lines |
| `product_id` | integer, FK → products | Product sold |
| `quantity` | smallint | Units, must be > 0 |
| `unit_price` | numeric(10,2) | Price charged before discount |
| `discount_pct` | numeric(4,2) | 0 – 0.50 (CHECK constraint) |

## Views and reporting objects

| Object | Purpose |
|---|---|
| `v_sales` | **The single revenue definition.** One row per line of a *completed* order, with `net_revenue = quantity × unit_price × (1 − discount_pct)`, `cost = quantity × unit_cost`, `gross_profit = net_revenue − cost`, and the customer's region and segment. All analysis queries and BI tools read from this view. |
| `mv_customer_rfm` | Materialized view of recency, frequency, monetary value and 1–5 NTILE scores per customer |
| `v_data_quality_issues` | Returns one row per problem found (orders without lines, orders before signup, items sold below cost, prices that differ from list price). Empty = healthy. |
| `fn_sales_summary(start, end, group_by)` | Revenue, profit, margin and orders for any date range, grouped by category, region, channel or segment |
| `sp_refresh_reporting()` | Refreshes `mv_customer_rfm` concurrently. Called after each load. |

## Business definitions

- **Revenue** counts **completed** orders only; cancelled and returned orders are excluded.
- **Region** in `v_sales` is the customer's home region, so online orders are attributed to where the customer lives.
- **Fiscal year** = July to June, labelled by the year it ends (FY2026 = Jul 2025 – Jun 2026).
- **Holiday period** = November and December.
